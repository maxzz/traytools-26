**Pros**
- Shorter import; no long named-import list to maintain when helpers are added/removed
- Clear origin at each use site (`measure.isValidSize` vs a free-floating name)
- Groups a cohesive API as one namespace — good when many related symbols are used heavily

**Cons**
- More verbose at call sites (`measure.MIN_CONTENT_W` vs `MIN_CONTENT_W`)
- Tree-shaking can be slightly weaker with some bundlers (usually fine for a local module)
- Types look a bit odd (`measure.Size2`); some teams prefer a separate `import type { Size2 }`
- Overkill when you only need 1–2 symbols

Here it’s a win: ~12 related symbols from one measure module, and the `measure.*` prefix makes the sizing logic easier to scan.
