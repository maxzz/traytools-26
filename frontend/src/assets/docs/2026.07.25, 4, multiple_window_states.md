### Persistence (`init.json`)
Named sizes plus the active key:

```json
{
  "windowSizeKey": "mini",
  "windowSizes": {
    "normal": { "x": …, "y": …, "width": …, "height": … },
    "mini":   { "x": …, "y": …, "width": 480, "height": 72 }
  },
  "bounds": { … }
}
```

- Legacy `bounds` migrates into `windowSizes.normal`.
- `bounds` is still written as a mirror of the active size for compatibility.
- Extra keys can be added later (e.g. per-tab layouts) without schema changes.

### Behavior
- **Toggle** saves the current rect under the active key, switches key, applies the other size, and persists immediately.
- **First use of mini** uses default `480×72` at the current position; later moves/resizes are remembered.
- **Startup** restores the last selected key’s geometry.
- **Quit** saves the active size’s current geometry (unchanged for maximized/minimized OS states).

### UI / API
- Header button toggles mini ↔ normal (`settingsBus.toggleWindowSize`).
- `setWindowSizeKey(key)` is ready for a future dropdown with more sizes.
