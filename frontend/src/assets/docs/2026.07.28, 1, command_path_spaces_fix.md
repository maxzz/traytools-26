Fixed on the Go side in `backend/tab-4-toolsmenu/config.go`.

**Cause:** When `cmdArgs` is empty, `splitFileArgs` treated the first space as the end of the executable. So:

`C:\Users\maxzz\Desktop\org page-qa2-test\notepad.exe`

became target `...\org` and args `page-qa2-test\notepad.exe` — matching the toast you saw.

**Fix:** Unquoted paths are resolved with a filesystem-aware split (longest existing prefix wins), similar to CreateProcess. If nothing matches and the string looks like a path (drive/UNC/separators), the whole string is kept as the target instead of truncating. Quoted forms and bare names like `notepad.exe file.txt` still behave as before. Env expansion now runs before the split so checks see real paths.

Rebuild/restart the Go app for this to take effect; no UI changes needed.
