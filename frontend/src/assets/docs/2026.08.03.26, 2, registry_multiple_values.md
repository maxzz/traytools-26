The plan is fully implemented: a registry tree leaf is now a key that owns an ordered `values[]` array, edited through a Motion reorder table in the props panel. Typecheck, all 99 tests, and the production build pass.

What landed, by layer:

- **Model** (`9-types-registry.ts`): new `RegValue` and `RegValueRef` types; `RegItem` swapped its flat `valueName`/`valueType`/`newValue` for `values: RegValue[]`. Uid assignment, cloning, and lookup (`findValueByUid`) reach into nested values, and labels became key-centric with `valueRefLabel` qualifying a value only when its key holds more than one.
- **Migration** (`6-json-serialize-dirty.ts`): `normalizeValues` wraps pre-`values` flat items into a single-value array and deletes the legacy fields, so old `registry.json` files and the localStorage cache both upgrade silently. `tools/registry.json` was rewritten in the new shape.
- **Ops** (`2-run-registry.ts`): the runners operate on `{ item, value }` pairs, so read results cache by *value* uid. Item- and group-level actions fan out over all values under the key; the new `doAsyncRegReadValueAtom` / `doAsyncRegWriteValueAtom` serve the per-row buttons. The Go bridge is untouched, as planned — it still takes one value per call.
- **.reg I/O**: import accumulates value lines into one item per key (repeated key sections merge), export expands each item's values back under its key. Tests cover the multi-value round-trip.
- **UI**: the new `3-5-props-item-values.tsx` renders the table — drag handle, value name, type, new value, current value with match coloring, and per-row read/write/delete. `Reorder.Group`/`Reorder.Item` with `dragListener={false}` plus `useDragControls` keeps the inputs editable while the handle drags. Delete is disabled at one row. The tree, quick list, and root/group panels now show value counts and key-centric wording.

Worth knowing: reordering and adding/deleting values happens only in the props table, so "add item" in the tree no longer copies the selected key path — new keys start fresh at `HKCU`. Since the values table is the one surface Reorder drives, it's worth a quick drag test in `p dev` to confirm the row animation feels right inside the scroll area.
