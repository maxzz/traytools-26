**What's there**

The new tab sits between Sync and Tools in the tab bar and follows the Copy Operations layout exactly: a tree on the left, properties on the right, and a results panel across the bottom. Selecting a registry value shows a root-key selector (all five hives), a key path field with a button that opens regedit at that key, a value name field, a type selector covering all six `REG_*` types, a new-value field that becomes a textarea for multi-string and binary, a registry-view selector for the 32/64-bit split, and Read/Write buttons. After a read, a panel underneath shows the current value with a green "Matches" or orange "Differs" badge against what you'd write. Groups and the root get the quick-access list with per-row Read and Write buttons, same as Sync and Copy Operations.

Writes go to the live registry behind an explicit button, with a confirmation dialog you can turn off from the root properties pane, and the existing elevation-restart flow kicks in for machine-wide hives.

**Import, export, and drag-and-drop**

Dropping a `.reg` or `.json` file anywhere on the tree always creates a new top-level group named after the file, holding every value it declares — the format is detected from the file's contents rather than its extension, so a renamed file still works. The same is available from both menus. Export writes either JSON or a Windows `.reg` file containing the desired values from the tree.

**Two things worth knowing**

The `.reg` handling is the part most likely to bite, so I tested it directly: 17 tests cover both header versions, all the `hex(N)` type codes, line continuations in wrapped hex payloads, escaped strings, key and value deletions (skipped with a warning rather than failing the import), and a full parse→serialize→parse round-trip. On the Go side, `.reg` files are read and written as UTF-16LE with a BOM and CRLF, which regedit requires; JSON stays UTF-8. Nine more Go tests cover that encoding and the value-text codec.

I also guarded against a footgun: an item with an empty key path would otherwise resolve to the hive root and quietly drop a value there, so writes reject it in both the frontend and the backend.

One small deviation from the plan: I left the optional `view` field off `RegGroup`. Each item resolves its own registry view, so a group-level one would have been an unused field.
