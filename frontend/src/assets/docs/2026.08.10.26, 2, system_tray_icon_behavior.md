# System tray icon behavior
_Exported on 8/9/2026 at 19:54:43 PDT from Cursor (3.15.6)_

---

**User**

When the application's main window is open, clicking the system tray icon minimizes the window and removes it from the taskbar; 
if the window is minimized, clicking the system tray icon restores it—this is normal behavior. 
However, if the window is visible on the screen and you click the taskbar icon, the window minimizes (which is correct), but a subsequent click on the system tray icon does not bring the window back; only a second click on the system tray icon restores the window. 
This needs to be fixed.

---

**Cursor**

I'll investigate the tray-icon and window minimize/restore logic to find why a taskbar minimize leaves the tray toggle one click out of sync.

The bug is clear: taskbar minimize doesn't update `windowVisible`, so the first tray click hides again instead of restoring. Checking for window events and any related tests.

Root cause: taskbar minimize leaves `windowVisible` true, so the first tray click hides instead of restoring. I'll treat a minimized window as not shown for toggle and the tray label.

Fixed. Taskbar minimize never updated the app’s `windowVisible` flag, so the first tray click still thought the window was open and hid it again; the second click restored it.

`toggleWindow` (and the tray Show/Hide label) now treat a taskbar-minimized window as not shown, so one tray click after a taskbar minimize restores the window. Rebuild/restart the app to pick up the Go change.
