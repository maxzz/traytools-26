**How it works**

Icons are keyed by the process executable path, not by HWND. After the tree loads, unique top-level paths are prefetched in one batched bus call. The same cache is reused for process-group folders and for the Path row in Properties.

**Backend** (`backend/fileicon/`)

- Extracts PE / `.ico` resources, with `ExtractIconEx` as fallback, and returns PNG data URLs
- New `fileicon` bus command: `getFileIcons`
- Tree nodes now include `processPath` on **top-level** windows only (child nodes stay small)

**Frontend** (`frontend/src/components/2-main/5-file-icons/`)

- Valtio `fileIconStore` caches icons by normalized path (idle / loading / ready / missing), with 16ms batching and in-flight dedupe
- `FileIcon` reserves a `size-3.5` slot so rows do not jump while the PNG loads
- `WindowNodeIcon` chooses:
  - **Process groups and top-level windows** — cached exe icon (style icon as fallback)
  - **Child windows** — `iconForWindowClass()` for known classes (Edit, ComboBox, SysListView32, …), otherwise the existing Square / Layers / AppWindow style icons

**Where they appear**

- Tree: exe icon on top-level windows and on process-group folders
- Properties: exe icon to the left of Path (both the window General tab and the process folder tab)
