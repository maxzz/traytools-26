It isn’t for the MRU data. `comboMruUi` only tracks **which combo popup is open**.

`comboMruStore` is serialized to localStorage on every change. Popup open/close is throwaway UI state. If `openKey` lived on that same proxy, every chevron click would write to disk, and a reload could restore a popup as open.

It’s a second store so persisted lists stay separate from that transient flag. Radix needs the flag because the Popover is **controlled**: picking an item has to close it (`closeComboMru()`), which an uncontrolled Popover does not do on its own.

So: two stores because one is saved and the other isn’t — not because the MRU list itself needed splitting.
